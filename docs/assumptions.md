# 假设与边界

## 预测假设

- 默认以历史交易中“有效正向销售量”近似需求；它不包含被库存约束而未成交的潜在需求。
- 预测窗口为未来 7 个自然日；数据按当地交易日期处理，未引入时区或节假日信息。
- 特征只使用预测起点之前的销量和日历字段，不使用未来销量、未来收入或全样本聚合量。

## 补货情景假设

- 提前期 `L`：默认 7 天，用户可调；假设在此期间没有补货到仓。
- 服务水平 `SL`：默认 95%，正态近似下 `z = Φ⁻¹(SL)`；界面约束在 50%–99.9%。
- 提前期需求：对未来 `L` 天的点预测求和；当 `L > 7` 时用最近 7 天日均预测外推，明确标为简化。
- 库存位置：`IP = 现货 + 在途 − 已预留 − 已欠交`。四项均为使用者输入，且 IP 可为负；公开数据无法验证其真实性。
- 安全库存：`SS = max(0, z × sqrt(L×σe² + μ²×σL²))`。`σe` 优先为所选模型滚动回测残差标准差；不足时为历史日销量标准差；`μ` 为预测日均需求，`σL` 为提前期标准差。`σL=0` 时退化为 `z×σe×sqrt(L)`。
- 补货点：`ROP = lead_time_demand + SS`。
- 建议补货量：`Q = max(0, ROP - available_inventory)`，结果向上取整到整件。
- 当前可用库存、在途、最小订货量、库容、报废、供应商产能均未知，因而库存为用户输入的假设值，未纳入在途与订单约束。
- 单位持有成本和缺货成本只用于比较参数敏感性：`holding_proxy = SS × holding_cost`，`stockout_proxy = max(0, ROP - available_inventory) × stockout_cost`。它们不是实际财务损益，也不能证明缺货减少或利润提升。

## 使用边界

本项目输出的是“在给定参数下应优先复核的 SKU 和理论补货缺口”。在投入业务使用前，必须接入真实库存、在途、供应提前期分布、MOQ/包装倍数、价格/促销、退货原因和缺货记录，并由业务人员审核。

## 参数字典、单位与允许范围

| 参数/变量 | 符号 | 单位 | 默认值/范围 | 数据来源 | 对结果的单调影响 |
|---|---|---|---|---|---|
| 预测日需求 | `\hat d_t` | 件/日 | 未来 7 个自然日 | 已选模型输出 | 增加会提高提前期需求、ROP 和建议量 |
| 提前期 | `L` | 天 | 默认 7；界面可调 | 用户假设 | 增加通常提高提前期需求和 SS（以 `sqrt(L)`） |
| 服务水平 | `SL` | 概率 | 默认 0.95；50%–99.9% | 用户假设 | 增加使 `z=Φ⁻¹(SL)` 增加，从而提高 SS/ROP |
| 标准正态分位数 | `z` | 无量纲 | `Φ⁻¹(SL)` | 由服务水平换算 | 随 `SL` 单调增加 |
| 需求/残差标准差 | `σ_d` | 件/日 | 优先回测残差标准差；不足回退历史日销量标准差 | 历史与回测产物 | 增加会线性提高 SS |
| 可用库存 | `I` | 件 | 默认 0；用户输入 | 用户假设，非 UCI 事实 | 增加会降低建议量，最低到 0 |
| 单位持有成本 | `c_h` | 成本单位/件 | 默认 0；用户输入 | 用户假设 | 仅提高持有成本代理，不改变 SS/ROP/Q |
| 单位缺货成本 | `c_s` | 成本单位/件 | 默认 0；用户输入 | 用户假设 | 仅提高缺货成本代理，不改变 SS/ROP/Q |

## 公式逐项展开与近似条件

设提前期内预测需求为：

`D_L = Σ(\hat d_t), t = 1 ... min(L, 7)`。

若 `L > 7`，没有未来第 8 天及以后的模型预测，本项目以最近 7 天预测均值 `mean(\hat d_1,...,\hat d_7)` 外推剩余天数：

`D_L = Σ(\hat d_1,...,\hat d_7) + (L-7) × mean(\hat d_1,...,\hat d_7)`。

然后计算：

```text
SS  = max(0, z × σ_d × sqrt(L))
ROP = D_L + SS
gap = max(0, ROP - I)
Q   = ceil(gap)

holding_proxy  = SS × c_h
stockout_proxy = gap × c_s
```

这些公式隐含下列近似：日需求/残差可用单一标准差概括；提前期内每日误差近似独立；服务水平可用标准正态分位数表示；库存持续复核；没有在途、MOQ、包装倍数、库容和供应约束。任何一项不成立，都不意味着公式“报错”，而是意味着结果更应被视为探索性情景。

## 参数边界示例

| 变化 | 公式上的直接后果 | 在业务上应怎样解释 |
|---|---|---|
| `L` 从 7 增至 14 | 点预测需求约翻倍（外推假设下），SS 从 `sqrt(7)` 按 `sqrt(14)` 增长 | 应先确认供应提前期而非仅调大参数 |
| `SL` 从 95% 提至 99% | `z` 增大，SS/ROP 增加 | 是服务目标与资金占用的取舍，不是模型准确率提升 |
| `I` 从 0 改为接近 ROP | `Q` 降至接近 0 | 只有输入是真实可用库存时才有业务意义 |
| 将 `c_h` 或 `c_s` 调高 | 成本代理增加 | 本项目不会据此自动“求最优 SL”，避免伪精确优化 |
| `σ_d` 很高 | SS 增加 | 表示预测/需求不确定性大，应优先查数据、模型和供应弹性 |

## 已知事实与假设的严格区分

| 类别 | 本项目中的例子 | 能否当作事实写入报告 |
|---|---|---|
| 已观测交易事实 | 原始行数、取消单计数、历史成交量、回测误差 | 可以，但必须标明数据范围和口径 |
| 模型估计 | 未来 7 天点预测、残差标准差、近似区间 | 可以，必须标明为模型输出/近似 |
| 用户输入假设 | 库存、提前期、服务水平、成本 | 可以，必须标明参数值，不可称为 UCI 提供的事实 |
| 未观测业务结果 | 实际缺货、库存余额、采购到货、利润改善 | 不可以；需要真实业务数据或上线评估 |
