# 需求与指标定义

## 功能需求

| 模块 | 必须产出 | 验收方式 |
|---|---|---|
| 数据质量 | 取消单、异常数量/价格、重复、缺 SKU、时间缺失、稀疏度审计 | DuckDB SQL 与 dbt 测试 |
| 需求主题表 | `mart_sku_daily_demand`（SKU×日） | 同一 SKU 每日唯一，日期连续补零 |
| 分层 | 稳定、周期、高波动、间歇/长尾 | 输出 SKU 层级与判定指标 |
| 回测 | 3 个以上时间起点、7 天窗口 | 禁止随机拆分；逐 SKU、模型、窗口留痕 |
| 评估 | WAPE、MAE、sMAPE、偏差、分层误差 | 指标表与报告可复算 |
| 补货 | 安全库存、补货点、建议量和敏感性分析 | 可改变参数，公式单测通过 |
| 看板 | 总览、评估、预测、补货、例外清单 | Streamlit 实际渲染数据与表格 |

## 指标字典

| 指标 | 公式/口径 | 用途与边界 |
|---|---|---|
| 正向销量 | `sum(Quantity)`；仅非取消、数量>0、单价>0、SKU 非空行 | 取消单单独审计，不与销售混算 |
| 销售额 | `Quantity × UnitPrice` | 用于 Top SKU 与价值分层；不等于利润 |
| WAPE | `sum(abs(y-yhat)) / sum(abs(y))` | 便于跨 SKU 汇总；当真实销量全为 0 时返回空值 |
| MAE | `mean(abs(y-yhat))` | 直接体现日均件数误差；不能单独跨不同销量 SKU 比较 |
| sMAPE | `mean(2*abs(y-yhat)/(abs(y)+abs(yhat)))` | 零销量较多时比 MAPE 更稳健；分母为 0 的项记为 0 |
| 预测偏差 | `sum(yhat-y)/sum(abs(y))` | 负值代表系统性低估，关联缺货风险；不是因果缺货概率 |
| 非零天占比 | 有销量天数/观察天数 | 识别间歇需求 |
| 变异系数 CV | 日销量标准差/日销量均值 | 识别高波动 SKU；均值为 0 时不计算 |
| 安全库存 | `z(服务水平) × σ(日需求或残差) × sqrt(提前期)` | 独立同分布近似，参数化模拟 |
| 补货点 ROP | `提前期内预测需求 + 安全库存` | 假设连续复核、即时补货决策 |
| 建议补货量 | `max(0, ROP - 假设可用库存)` | 未考虑 MOQ、在途和库容；不能视为采购订单 |

## 为什么不用 MAPE

SKU 日销量包含大量零值；MAPE 会除以零或极度放大低销量天的误差。因此主报告使用 WAPE 和 MAE，并用 sMAPE 作为零需求场景下的辅助比率指标。

## 指标计算细则与边界案例

| 情况 | WAPE | MAE | sMAPE | 偏差 | 本项目处理理由 |
|---|---|---|---|---|---|
| 某天真实销量为 0、预测大于 0 | 计入绝对误差 | 计入绝对误差 | 分母为预测值，可计算 | 计入高估 | 不能把零销量日直接丢掉，否则会奖励无根据备货 |
| 某天真实和预测都为 0 | 对总分子/分母无额外贡献 | 误差为 0 | 该项定义为 0 | 无贡献 | 避免 0/0，同时表达“正确预测无需求” |
| 一个窗口真实销量总和为 0 | 返回空值，不把比率伪造为 0 | 仍可算 | 仍可逐日算 | 返回空值 | 没有销量分母时 WAPE/偏差没有稳定商业解释 |
| 高销量 SKU 与低销量 SKU 汇总 | 以总销量加权，天然更关注成交量 | 单位为件，不能直接跨量级解释 | 每天等权，易受小量/零值日影响 | 以总销量归一 | 所以四项要并列看，不能只挑一个“最好” |
| 全部 SKU 合并 | 反映组合误差 | 给出日均件数误差 | 作为辅助 | 检查系统性高估/低估 | 还必须看分层和 SKU 级，防止大 SKU 掩盖长尾问题 |

## 指标选择到业务动作的映射

| 观察到的信号 | 不能直接推出的结论 | 推荐复核动作 |
|---|---|---|
| WAPE 高 | “库存一定不足” | 检查模型选择、近期需求变化、SKU 是否应从日级改为周级/间歇策略 |
| MAE 大 | “模型很差” | 先与该 SKU 的日均销量和销售价值比较，确认量级是否可接受 |
| 偏差为负 | “已经发生缺货” | 关注低估风险；用真实库存、在途和服务目标重新计算情景 |
| 偏差为正 | “一定积压” | 复核高估及预测上限，不根据交易数据推断真实库存积压 |
| sMAPE 与 WAPE 结论相反 | “某指标算错了” | 查看零值比例、销量权重和 SKU 结构；在报告中保留冲突而非挑选有利指标 |

## 结果验收阈值与非阈值原则

本项目的验收重点是**方法正确、证据完整、边界清楚**，不是预先承诺某个 WAPE 数值。原因是公开数据、选定 SKU 和时间窗口都影响误差。固定的过程阈值如下：

| 检查 | 规则 | 实际执行状态 |
|---|---|---|
| 时间完整性 | 正式选模 SKU 必须覆盖 3 个起点 × 7 天 = 21 个测试观测 | 已执行；25 个 SKU 入选 |
| 特征边界 | 训练/滚动统计必须早于预测起点 | 已通过滚动切分设计和单测验证 |
| 主题表粒度 | 每 SKU 每日最多一行 | 已由 dbt 测试验证 |
| 数据质量透明度 | 取消、异常、候选重复、缺失、稀疏必须有可导出计数 | 已生成 11 项审计 |
| 模型比较透明度 | 三个候选模型和四类指标都保留 | 已生成总体、窗口、分层、SKU 级结果 |

## 决策规则

例外 SKU 指满足以下任一条件：预测偏差显著为负、分层 WAPE 位于较高水平、预测残差波动高且近期销量高、或建议补货量为正且参数变化敏感。阈值在代码中显式配置，而非由看板文案暗示真实风险。
