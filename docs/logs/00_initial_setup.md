## 3. 在编码前锁定的关键决策

| 决策 | 选择 | 依据 | 被拒绝/延后的做法 |
|---|---|---|---|
| 需求粒度 | SKU×日 | 补货提前期和预测窗口都按天；可保留周内模式并直接累加提前期需求 | 直接做 SKU×周会掩盖短提前期内的波动；只在日级过稀疏时作为升级方案 |
| 需求定义 | 有效正向交易量是成交需求代理 | UCI 只有交易行，没有库存与缺货观测 | 不能称其为完整潜在需求 |
| 取消单 | 独立标记、统计，不计入正向销量 | 取消与负数量可能反映退货/撤销，混入会扭曲补货需求 | 不能简单把所有负数求和后抵减销量 |
| 异常数量/价格 | 保留在审计层，排除在需求聚合层 | 可复核且避免负/零值污染销量和销售额 | 不直接物理删除原始行 |
| 重复 | 报告完全重复与候选业务重复；候选重复不自动等同系统错误 | 原始数据没有可信订单行唯一键可验证所有重复 | 不在未确认前夸大“去重带来的提升” |
| SKU 分层 | 稳定、周期、高价值高波动、间歇/长尾 | 一种模型/一个平均误差不能公平描述全部 SKU | 不将长尾与高价值 SKU 混合后只报一个总体分数 |
| 回测 | 三个滚动、7 天预测窗口 | 模拟实际时点只能看到过去的情形 | 不使用随机 train/test split |
| 评估 | WAPE 主聚合、MAE 量纲误差、sMAPE 零值稳健补充、偏差监控低估 | 日销量零值使 MAPE 不稳定；单一指标容易掩盖风险 | 不宣称某模型“全面最好” |
| 补货 | 安全库存/ROP/建议量的参数化情景 | 缺少真实库存、在途、供应提前期、MOQ 和成本 | 不输出可执行采购订单或利润改善承诺 |
