# 2026-08-04：工作区缓存与本地服务清理

## 触发原因与目标

用户要求清理当前工作区中多余的临时文件、缓存文件、后台进程和本地服务。目标是释放可再生产物占用的空间、避免遗留本地服务端口，同时不破坏项目可运行性、原始数据、DuckDB 结果或已安装环境。

## 盘点过程

先执行只读检查：Git 分支状态、项目内缓存目录、`.DS_Store` 文件和 Streamlit 默认验证端口 `8502`。初始扫描发现 `app/__pycache__`（20 KB）、`src/__pycache__`（76 KB）、`tests/__pycache__`（88 KB）、`.pytest_cache`（20 KB）、`dbt/target`（约 1.4 MB）和 `dbt/logs`（约 916 KB），合计约 2.5 MB。这些目录分别由 Python 解释器、pytest 与 dbt 自动生成；删除后会在下次运行时再建，不含源代码或业务数据。

扫描还发现 `.venv` 内存在大量 Python 字节码缓存。**本次有意保留 `.venv`**：它是本机已安装的可运行依赖环境，不是项目临时产物；删除会导致无法直接运行测试和看板，并可能需要重新安装依赖。原始 Excel、压缩包、`data/retail.duckdb`、`data/processed/` 以及 Git 元数据同样不在清理范围。

## 执行内容

已精确删除以下已盘点目标：

- `app/__pycache__`
- `src/__pycache__`
- `tests/__pycache__`
- `.pytest_cache`
- `dbt/target`
- `dbt/logs`
- 项目根目录与 `docs/` 下的 `.DS_Store`

此前为看板验证启动的 Streamlit 已在当时收到停止信号。本阶段进一步用 `lsof -nP -iTCP:8502 -sTCP:LISTEN` 检查，未发现 8502 端口监听者。系统权限不允许 `pgrep` 枚举全部进程，因此没有对无关系统进程进行猜测性终止；这避免误杀其他任务。

## 验证结果、风险与下一步

删除后再次检查，项目根目录（排除保留的 `.venv`）中不存在上述缓存目录或 `.DS_Store` 文件；8502 端口无监听服务；`git status --short --branch` 显示 `main...origin/main` 且无未提交改动。本阶段未遇到阻塞问题。

剩余风险是下次运行 pytest、dbt 或 Python 时，这些缓存会被正常重新生成；这是工具设计的预期行为，不代表清理失败。若未来确实要回收更多磁盘空间，可在用户明确同意后删除 `.venv`，但这会移除项目运行环境并需要重新安装依赖，故本次不执行。
