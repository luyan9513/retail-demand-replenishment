# 实施计划与风险

## 阶段计划

1. 建立文档、目录、依赖清单、数据契约和许可边界。
2. 编写 DuckDB/dbt 数据分层、质量 SQL 与 Python 导入逻辑。
3. 编写特征、分层、滚动回测、评估和补货公式，并用单元测试锁定关键口径。
4. 构建 Streamlit 看板与报告模板；数据到位后生成真实输出。
5. 下载并导入经确认的数据，运行 dbt、回测、报告和应用验证；用实际数值回填 README/报告/简历 bullet。

## 已知风险与处理

| 风险 | 影响 | 控制办法 |
|---|---|---|
| UCI 数据下载与许可 | 可能产生无归因的数据使用 | 已从 UCI 官方 CDN 下载 43.5 MB 文件；README、数据卡和第三方声明保留 CC BY 4.0 归因 |
| Excel 字段名/格式差异 | 导入失败或列识别错误 | `ingest.py` 支持常见列名映射并在缺列时报错 |
| 稀疏日销量 | 日级模型误差不稳定 | 质量审计、独立分层、Top SKU 范围和周级升级条件 |
| 无真实库存/成本 | 可能被误解为优化收益 | 参数显式标“假设”，报告限制声明，禁止收益叙述 |
| 复杂模型表现差 | 不能展示预期模型“先进性” | 坚持保留基线，按业务误差选择模型 |
| DuckDB/dbt/Python 版本不一致 | 本地运行失败 | 固定 requirements；DuckDB 1.5 实际要求 Python 3.10+，运行前检查解释器并记录日志 |

## 变更纪律

每阶段完成后，先更新 `docs/logs/` 和 `docs/traceability.md`，再报告实际运行命令、结果、剩余风险和下一步。所有数据数值必须来自可复现命令。
